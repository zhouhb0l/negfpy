# External storage boundary

Configure host-specific datasets, generated campaigns, environments and recovery storage through the host's private workspace registry and the project's established mechanisms. Do not publish personal paths, private instructions, credentials or local runtime details in shared metadata.

Keep selected compact inputs and provenance that the project intentionally tracks under its existing policy. External storage is not a reason to discard those selected materials or ignore scientific files by extension.

Retain historical recovery material and its original provenance. A clone alone does not preserve local edits, ignored files or unsaved editor buffers. Record the actual preservation scope privately before changing a working checkout.

The portable path example supplies placeholders, not evidence that storage exists or that a runtime loader is installed.
