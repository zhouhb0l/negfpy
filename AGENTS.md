# NEGFPy contributor guidance

Read README.md, PROJECT_NOTES.md and the relevant development documentation before making changes. This guide supplements existing software, scientific and release rules; it does not replace them.

Consult the host's private workspace registry for inherited instructions, physical checkout locations and local configuration. Keep private instructions and host details out of shared metadata.

Preserve existing work, release tags and distinct experimental branches. Folder organization does not authorize resetting a checkout, merging an experiment or changing a validated release.

Share reusable source, tests, portable examples and documentation under the existing project policy. Configure datasets, environments, generated campaigns and recovery storage privately. Preserve selected inputs and provenance already intentionally tracked by the project.

Use focused existing checks appropriate to a change. Organization metadata creates no new software release or validation claim.
