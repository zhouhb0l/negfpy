## Independent reference generation

The release reference is generated by phono3py 4.4.0, not by the NEGFPy
linewidth kernel. The pinned force-constant stage first creates full and
compact FC2/FC3. The MPI reference stage then assigns one complete target
\(q\) point to each worker. Each worker performs phono3py's complete internal
triplet and branch calculation for that target. Rank zero merges complete
target slabs in canonical generalized-regular-grid order; it never performs a
floating-point MPI reduction.

The MPI wrapper is deliberately separate from
`generate_phono3py_si_reference.py`. Its orchestration record authenticates
both the unchanged serial generator and the wrapper, the pinned source
checkout, force stage, environment, selected full mesh and bands, per-target
artifacts, canonical merge, and final reference HDF5. Historical serial
reference bundles remain readable, but an MPI-generated release reference
must carry and pass this additional record.

## Complete-target-q MPI contract

### Numerical boundary

- One task owns one complete selected target \(q\) point and invokes the
  unchanged serial linewidth kernel. The complete internal \(q'\) and branch
  sums stay inside that task; they are not partitioned across ranks.
- In MPI mode rank zero is a coordinator. MPI messages carry task identifiers
  and terminal status, while each worker publishes the complete numerical
  fields as an immutable HDF5 artifact on the shared filesystem.
- Rank zero validates the task artifacts and copies them into canonical
  target-\(q\) order. There is no floating-point MPI reduction, so rank count
  and task finish order cannot change the scientific summation order.

### Exact restart and merge

- `--resume` accepts only an existing run directory whose immutable manifest,
  checkpoint identities, artifact hashes, schemas, shapes, dtypes, metadata,
  and scientific controls validate against the current campaign. Valid
  completed tasks are reused without calling the numerical kernel again.
- An immutable HDF5 artifact left by an interruption before its checkpoint
  sidecar was published may be adopted without recomputation, but only after
  the same strict identity and content validation.
- Mismatched, corrupt, truncated, duplicate, or cross-campaign artifacts are
  errors. A canonical merge requires one validated completed checkpoint per
  target \(q\), verifies fields shared by all tasks, and records both per-task
  and merged dataset SHA256 values.

### Provenance boundary

Rank zero authenticates a clean source revision with no dirty-tree bypass,
the passed serial report, pinned inputs, environment lock, full scientific
problem hash, controls, and thread limits before scheduling work. The
campaign and task identities bind those records to the source revision,
source-tree hash, environment hash, control hash, problem hash, input hashes,
and individual target \(q\). Workers reconstruct the same manifest from the
broadcast descriptor, and the explicit inputs are rechecked for changes
before the final summary is published. A memory-limit override may permit an
exploratory run, but marks it noncertifying.

## Bounded \(V^{(3)}\) comparison on the full mesh

Material certification compares gauge-invariant
\(\lvert V^{(3)}\rvert^2\), not individual eigenvectors inside degenerate
subspaces. Enumerating every mode block on the \(11^3\) mesh would make the
sample manifest itself unnecessarily large. The bounded-v2 selector therefore
uses a preregistered two-pass streaming algorithm:

1. find the global nonzero strength scale and deterministic global maximum;
2. maintain deterministic fixed-capacity reservoirs over every populated
   normal/Umklapp, target-band, route and strength stratum.

The output contains at most 512 blocks, includes every band, both scattering
classes, all populated strata, and the global maximum, and promotes at least
two blocks per populated stratum. It explicitly does **not** claim exhaustive
target-\(q\) coverage. Task-level MPI partitions only complete target-\(q\)
reference slabs. Rank zero merges integer identities and fixed accumulator
states in canonical order, producing the same scientific JSON bytes as the
serial bounded-v2 algorithm.

## Final `0.2.0` evidence decision

No individual campaign is allowed to declare the release passed. The target
runner and external phono3py comparison always record
`release_certified=false`. The final immutable evidence aggregator is the
only component that may set it true, and only after authenticating all of the
following on one exact clean installed `0.2.0` commit:

- the complete external \(11^3\) phono3py comparison;
- fresh, non-resumed, full-\(q\), full-band MPI campaigns at \(3^3\) and
  \(5^3\);
- monolithic-serial versus MPI equality for every numerical, routing and
  metadata field at `rtol=1e-10`, `atol=1e-12`;
- complete immutable serial operands plus an independent final-aggregator
  rerun of the authoritative serial kernel at both \(3^3\) and \(5^3\);
- exhaustive compact/full FC3 physical-block and canonical-term equality,
  together with all redundant full first-axis translation rows; the
  reciprocal FC3 cross-check remains explicitly sampled;
- identical FC2, FC3, crystal mapping, normalized input manifest,
  environment lock, source tree and imported package payload;
- all task manifests, executions, per-task checkpoints and artifacts,
  canonical merges, HDF5 results, reference-generation records, and report
  digests, re-read and re-hashed before and after aggregation, with every
  target-task merge independently rebuilt and all HDF5 links/storage kept
  inside the tracked files; and
- package, thread, memory and no-override qualification.

An exact checkpoint resume is valid scientific evidence for the \(11^3\)
external comparison, but it cannot satisfy the deliberately stricter fresh
MPI-equality gates at \(3^3\) or \(5^3\).
